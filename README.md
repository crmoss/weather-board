# 현장 일정 날씨판

오늘 현장 일정과 지역별 날씨를 한 화면에서 보고, 날씨 때문에 주의 · 중지를 검토할 일정을 표시합니다. (교육용 가상 데이터)

## 여는 법
- 배포 주소(HTTP/HTTPS)에서 엽니다.
- 인터넷 : (배포 후 Vercel 주소를 여기에 적기)

## Supabase 설정 (F-06)

1. Supabase 프로젝트를 만들고 SQL Editor에서 `setup.sql` 전체를 실행합니다. 테이블·제약·RLS·가상 일정 6건이 생성됩니다. 기존 `wx_tasks`가 있으면 실행이 중단되며, 재실행 전 기존 스키마를 확인하세요.
2. 프로젝트의 Connect 또는 API 설정에서 프로젝트 URL과 공개용 publishable 키(또는 기존 anon 키)를 확인합니다.
3. `config.js`의 빈 문자열 두 곳에 각각 URL과 공개용 키를 입력합니다. `sb_secret_`로 시작하는 키와 `service_role` 키는 절대 입력하지 마세요.
4. 사이트를 배포한 후 새로고침합니다. 설정이 없거나 연결에 실패하면 화면에 안내가 표시됩니다.

로그인 없이 누구나 일정을 조회·추가할 수 있는 교육용 설정입니다. 수정·삭제는 허용하지 않으며 가상 데이터만 사용합니다. 다른 사람이 추가한 일정은 새로고침하면 보입니다. 이전 JSON과 브라우저 저장 일정은 자동으로 이관하지 않습니다.

## 확인 방법

- T-01: 설정 후 기본 일정 6건이 표시되는지 확인합니다.
- T-02: 가상 일정을 추가하고, 새로고침 또는 다른 브라우저에서 같은 배포 주소를 열어 저장 여부를 확인합니다.
- T-03/T-04: 지역별 날씨와 `?test=wind`의 고소 일정 중지 검토를 확인합니다.
- DB 제약: SQL Editor에서 region='서울' 또는 kind='기타'인 행을 INSERT하면 CHECK 제약 오류로 거부되어야 합니다. NOT NULL과 빈 문자열 제약도 적용합니다.
- 공개용 키로 UPDATE/DELETE하면 권한 오류로 거부되어야 합니다.
- 오늘판단md로저장 버튼으로 현재 표를 Markdown 파일로 내려받습니다.

## 파일
### 지역별 JSON API (F-07)

- Vercel 재배포 후 `/api/kma?region=대전`으로 호출합니다. 지원 지역: 세종·대전·태안·보령.
- Vercel의 `KMA_KEY`에 **공공데이터포털 기상청 단기예보 조회서비스** 인증키를 설정합니다. 기상청 API허브의 authKey와는 다른 인증 방식입니다. 해당 서비스 활용신청이 승인되어 있어야 합니다.
- 기존 `config.js`의 Supabase 공개 설정을 서버에서도 사용하며 RLS 조회 권한을 따릅니다. 추가 DB 테이블이나 SQL 실행은 필요 없습니다.
- JSON의 `tasks`는 해당 지역 DB 일정과 `judgment: { level, text }`, `weather`는 `tempMax`, `windMax`, `rainProb`, 단위와 발표시점을 포함합니다.
- 한국 시간 오늘 전체 24시간의 최댓값을 전날 20시 발표 예보에서 계산합니다. 날씨·판단을 DB에 저장하지 않습니다. 기존 화면은 Open-Meteo를 사용합니다.
- 확인: T-05~T-07(PRD.md). 서버 설정 누락은 500, DB·기상청 오류는 502입니다. 로컬 정적 서버에서는 이 API가 실행되지 않으므로 Vercel 배포 환경에서 확인합니다.
